# DoujinDigDatabase（digjindb）

**同人音乐展会专辑数据库** · https://www.digjindb.top

按展会（M3 / Comic Market / 例大祭…）整理同人音乐专辑，记录专辑、社团、
艺人、曲目、封面与发售信息，支持按展会/社团/年份/标签筛选与全文搜索。

纯 Python 标准库实现，**零第三方依赖**。

---

## 功能

- **专辑** —— 标题（原名/罗马音）、社团、艺人、发售日、展会、展位、
  编号、价格、曲目表、封面、制作人员、外链
- **展会** —— 两级结构：系列（缩写/全称/LOGO/wiki）+ 会次（`[M3] M3-2026秋 (M3-58)`）
- **社团 / 艺人** —— 独立词条，含成立时间、活动类型、成员、别名
- **搜索** —— 标题 / 社团 / 艺人 / 曲目 / 编号全文检索
- **用户** —— 注册、邮箱验证、收藏、关注社团/艺人、评论、编辑审核队列
- **主页** —— 头像、加入时间与最后活跃时间、收藏专辑（带封面）、关注的社团/艺人
  （带头像）、贡献记录（同一目标的多次改动合并计数）
- **数据看板** —— `/dashboard` 仅站务账号可见：访问量、独立访客、热门页面、
  最近访问（含访客真实 IP）、最近改动、服务器 CPU / 内存 / 硬盘 / 负载
- **编辑** —— 编辑者可在网页上修改词条，改动留修订历史
  - 表格化编辑：封面（可裁切）/ 标题 / 出品信息 / 分类 / 简介 / 制作人员 / 外链 / 多碟曲目
  - 曲目可整段粘贴（含 `Disc 2` / `第2碟` 这样的分碟行），区里自带「粘贴文本识别曲目表」按钮：点一下只在前端解析并填进下方表格，不提交、不发请求，点最下面的「保存」才写库；
    粘进来的是整段 infobox 也行，`tracks || ` 前缀会自动剥掉。填过之后再改表格，保存时以表格为准，不会被粘贴原文盖回去
  - 制作人员也能整段粘贴（每行「职责: 名字」），括号里的链接与 `@用户名` 自动忽略；按钮同样是「粘贴文本识别制作人员」，只填表不提交
  - 粘贴 `dddb infobox` 一段文本一键填整张表单，也可反向导出
  - 编辑草稿自动存本地，带版本历史，保存失败不会丢内容
  - 重复专辑合并：指定目标专辑，并勾选这次要合并哪些部分
  - 删除专辑、附图（不含封面，可加备注）
  - 修改记录逐字段对比新旧值

## 运行

```bash
python -m dddb public --root . --host 127.0.0.1 --port 8940
```

首次运行前：

```bash
python -m dddb init       # 建目录与默认配置
```

配置文件 `config/config.toml`，站点相关的设置在 `[public]` 段。

### 部署

需要一个 WSGI 之外的最小 HTTP 服务即可；生产环境前面放反向代理（Caddy / Nginx）。

```toml
[public]
sessions_db = "data/sessions.sqlite3"
base_url = "https://www.digjindb.top"
behind_proxy = true
rate_limit_enabled = true
```

## 编辑约定

- **详情页**右上角「编辑这张专辑 / 修改记录」与左侧「新建专辑」同排、同尺寸，
  不单独占一行。
- **新建页**与编辑页是同一套卡片，版面一致：左大图、中间加号（封面 + 附图）、
  右边说明与上传按钮；最后一行按钮整排右对齐。没有封面时那格是加号按钮。
  建好之后直接落到详情页，不回编辑页。
- **封面**从 infobox 地址抓取时先缓存（`POST /cover-cache/new`，存
  `covers/pending/<token>`，24 小时清理），点保存才转成正式封面；自己换了图，
  缓存的这张会被删掉。
- **草稿**存在浏览器 `localStorage`（`dddb:edit-draft`），提交表单不删，
  等真的落到详情页才清 —— 保存失败退回编辑页时内容还在。
- **附图**不参与封面，只是附加照片，可加备注；详情页有多张图时右上角可点着切换。
- 外链名按域名自动识别（`shop.geekjack.net` → Geek Jack、`tanocstore.net` → TANO*C Store 等），可以改写成自己的叫法
- **每一碟可以单独命名**（编辑页碟头输入框），名字会显示在详情页碟头，也能用碟名搜到这张专辑；
  碟头按钮是「↑ 上移 / ↓ 下移」换碟顺序，曲目行可以跨碟拖动。
  infobox 里用 `disc || 2: Nightmare` 一行表示分碟，之后的曲目都算这一碟；单碟不写这行。
- **出品信息分两套**：同人展侧（展会 / 品番 / 价格 / 展馆 / 展位）与独立同人侧（发布平台）；
  共享「原作」一项（东方 / 蔚蓝档案 / 原神 这类 IP，原创留空），另有「制作人」。
- **制作人员粘贴**里每行取**最后一个**冒号前的部分当职责（`instrument:Piano: 甲` →
  职责 `instrument:Piano`），所以带冒号的职责不会被打断；括号里的链接先整段剥掉再找冒号。
- **最后活跃**取的是真·活跃时间（每次请求刷新，5 分钟内不重复写库），不是登录时间。
- **数据看板**的访问日志存在 `data/site_visits.sqlite3`（与用户库同目录，因为它必须
  可写，而程序目录是只读的），只留 30 天，图片与静态资源不计入。
- 服务在反向代理后面时，访客 IP 从 `X-Forwarded-For` / `CF-Connecting-IP` 取；
  TCP 对端是回环地址就自动信任这些头（外网客户端造不出回环对端），所以不必额外开关。
- 站务独有的三个入口（审核队列 / 用户管理 / 数据看板）收在导航的「站务」下拉里，
  手机上其余链接不会因此挤出屏幕；下拉是原生 `<details>`，没有脚本也能开合。
